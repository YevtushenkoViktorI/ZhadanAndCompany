# Архітектура сайту

## Принципи

- Кожна сторінка лише збирає готові секції та отримує контент зі словника або CMS.
- `components/ui` містить низькорівневі інтерактивні примітиви.
- `components/shared` містить універсальні компоненти проєкту.
- `components/layout` відповідає за глобальний каркас.
- Доменні компоненти групуються за функцією: `home`, `services`, `works`, `order`.
- Усі публічні маршрути починаються з locale, наприклад `/uk`, `/fr`, `/ar`.
- Жоден компонент не перевіряє мову через ланцюжки `if`; він отримує готовий переклад.
- Шрифти зберігаються в `app/fonts` і збираються разом із застосунком.

## Потік даних

`route → dictionary/CMS → feature component → shared/ui components`

## Локалізація

Підтримувані мови визначаються тільки в `i18n/config.ts`. Словники мають однакову
структуру й завантажуються окремо для кожної мови. Після підключення CMS записи
повинні зберігати локалізовані поля, а системні написи залишаються у словниках.
RTL-локалі визначаються централізовано через `rtlLocales`; для арабської весь
локалізований layout отримує `dir="rtl"`, а компоненти використовують логічне
позиціонування й автоматично змінюють напрямок.

## Шрифти

Manrope використовується для основного тексту, Unbounded — для заголовків і
акцентів, Noto Sans Arabic — для арабської локалі. Усі variable-font файли лежать
у репозиторії; зовнішніх запитів під час перегляду сайту немає.

## Подальше розширення

1. Додати доменні типи для замовлень, послуг і виконаних робіт.
2. Побудувати окремі feature-компоненти, не розширюючи файли сторінок.
3. Підключити CMS через адаптер у `lib/cms`, не прив'язуючи UI до SDK CMS.
4. Додати locale-aware metadata, sitemap та canonical/alternate links.
5. Додати тести для словників, роутів і критичних компонентів.

## Контентні моделі

Типи послуг знаходяться в `types`, а локальні джерела даних — у `content`.
Сторінки й компоненти не повинні імпортувати SDK майбутньої CMS напряму:
адаптер CMS згодом повертатиме ті самі типи даних.
